## 用户界面与行为

- 设置页在原“影片刮削”后添加 **MDCz 增强刮削**。连接地址、掩码密钥、连接测试、启用开关、翻译开关、角标开关/位置在同一处；明确未保存、保存中、测试成功与错误状态。窄屏表单自动单列，复用现有 UI 组件，不新增 UI 依赖。
- 媒体库沿用原刮削任务、进度、取消/重试和“重新刮削”入口。保存设置不会启动全库重建；应先选择一部影片验收，再按需要重建。
- 详情的介绍位于基本资料后、预览前。长介绍默认三行，可展开；文本转义，隐私模式隐藏。媒体库优先读已保存 NFO 介绍，发现详情只在打开当前影片时补充，列表预加载不会调用 MDCz 或下载其图片。
- 增强开启后，MDCz 提供聚合资料、介绍、可选翻译及图片候选；原刮削来源设置仍可保留，关闭增强后恢复原解析路径。服务失败显示可重试任务错误，不将失败伪装成空成功。
- 真正入库时用实际视频文件名推断中字、破解、流出、无码及分辨率角标；多分集取共同属性。来源是文件名约定，不是内容鉴定；不使用网上磁力、站点剧情或题材标签推断当前文件属性。STRM 的真实分辨率、内嵌字幕及随后下载的外置字幕未进行媒体探测，未标记时不凭空补标。
- 内置角标由 MDCz 实际合成到 JPEG，保存至 Miyabi 图片缓存并随 NFO/STRM 导出；资源标签以独立 provider 写入 NFO tag/genre，供 Emby 读取。保留原始横向 fanart，列表缩略图使用生成的海报。初版不接入可变自定义角标图片，以保证样式可由固定引擎版本和位置准确标识。

## 服务边界

Miyabi 是最终媒体文件、目录、NFO、STRM 和字幕的唯一写入者。桥接服务没有挂载真实媒体库，仅交付 JSON 和图片。MDCz 的公开服务接口是路径任务接口，不能直接替代纯资料查询；因此桥接单独封装其 runtime。没有修改或复制 MDCz 的核心源码。

`extensions/mdcz-bridge/adapter.ts` 集中依赖 MDCz 的聚合、翻译、网络、文件名识别和角标模块；其余桥接 HTTP/校验代码只依赖自有协议。桥接依赖仍是内部 runtime，升级时需要契约核对，不能承诺零适配。

| 新增模块 | 职责 |
| --- | --- |
| `internal/mdcz/` | 独立设置、受限 HTTP 请求、元数据适配、介绍缓存、原图与衍生图管理 |
| `internal/api/mdcz_extension.go` | 可选能力，原鉴权/同源/no-store 下的新路由 |
| `internal/library/scrape/artwork_extension.go` | 可选封面装饰与持久检查点；旧调用方不必实现 |
| `internal/nfo/movie_extensions.go` | 原图摘要、样式摘要和资源标签，随 NFO 保存/恢复 |
| `web/src/api/mdcz.ts`、两个独立界面组件 | 独立查询键、设置保存、介绍渲染 |
| `extensions/mdcz-bridge/` | 固定上游源码上的独立服务、协议测试及部署配方 |

原文件接入清单：

| 接入处 | 原因及升级时检查 |

旧函数签名保持不变；少量结构增加可选字段。这里选择直接保留标准 `<plot>`，避免后置 XML 修改在重建时丢失。原 `ExportLocalMovie` 无需接入在线服务，它直接重放已保存介绍、角标海报和原 fanart。导入旧 NFO 也能保留 plot；相应旧测试从“丢弃介绍”更新为“介绍与原图关联往返保留”。已有来源评分按原分制保留；MDCz 聚合评分没有明确分母，桥接不伪造评分，重刮保留同影片已有评分。新片另复用 Miyabi 原生的 JavDB 精确匹配查找，保留 JavDB ID、原分制评分及评论/磁力关联；不重复运行全部原生刮削器。身份冲突拒绝合并；新入库时 JavDB 临时失败允许使用 MDCz 已确认资料，但可能暂缺关联和评分，待网络恢复后重刮补齐；刷新已有资料时该失败会中止覆盖。独立 JavLibrary 评分逻辑保持原样。详情只补介绍时不会追加该 JavDB 查询。

## 接口和数据

Miyabi 新路由：GET/PUT `/api/extensions/mdcz/settings`；POST `/api/extensions/mdcz/test`；GET `/api/extensions/mdcz/synopsis?code=...`。设置 GET 不返回密钥；PUT 密钥省略保留，显式空串清除（关闭状态才可清除）。连接测试针对当前表单且不保存设置，校验协议和固定引擎 SHA。

桥接新路由：GET `/v1/health`，POST `/v1/metadata`，GET `/v1/images/<sha256>`，POST `/v1/poster`。均要求 Bearer 密钥；禁用重定向，密钥不进入 URL/浏览器图片/播放链接。只有 metadata 发放的摘要图片引用能被读取，浏览器不能借桥接指定任意 URL。错误正文不透传上游凭据或代理细节。

桥接一次处理一个资料/图片任务，Go 调用方按上下文排队；健康检查可并行。来源聚合默认并发 2，sharp 并发 1，单任务 150 秒预算。请求或页面关闭会传递取消。完整重刮遇到部分来源失败时拒绝覆盖旧资料；介绍来源为空不代表存在中文介绍，翻译失败也不会写作成功。

Miyabi 扩展文件位于 `<data>/extensions/mdcz-v1/`：

- `synopsis-*`：成功取得的介绍持久缓存，按引擎、服务地址、翻译设置和番号隔离；重刮成功会更新。
- `original-<sha>.jpg`：用于恢复的未标记原图，不受旧图片清理任务删除。属于扩展恢复资料，须随数据目录备份。
- `derived-<sha>.json`：派生海报及标签，键含协议、引擎版本、番号、原图摘要、角标位置和排序后的实际文件名。重复任务与重试复用，改位置重新从原图合成。

桥接自己的 `/data/assets` 保存图片来源引用，临时海报工作目录用后删除。资料与原图没有定时清理；停止任务后可手动清理 `synopsis-*`、`derived-*` 来重新获取/生成。不要清理仍被 NFO 引用的 `original-*`；缺失时会明确要求重新刮削，不在已标记图片上重复叠加。导入 NFO 后，已有导出图片可以离线重放；恢复重新合成功能还需保留原图目录。备份 Miyabi 数据、桥接数据和只读配置。

## J4125 部署配方（尚未构建）

`extensions/mdcz-bridge/Dockerfile` 固定拉取上述 MDCz SHA，按上游 frozen lock 安装/打包，再只保留运行依赖与字体。服务端使用 Node 24、sharp/impit，无 Electron 运行时；配方仅允许 amd64。它是自有桥接镜像，不能用普通 MDCz 服务地址代替。

恢复构建授权并通过回归后：

1. 构建本 PR 的 Miyabi 测试镜像及桥接镜像；当前正式 `v0.3.0` 不含此功能。提供的 Compose 明确要求填写 `MIYABI_IMAGE`，避免误用旧版。
2. 按 `mdcz.example.json` 配置站点、代理与翻译引擎，作为 `/config/mdcz.json:ro` 挂载。该配置属于桥接服务，未复用或修改用户原 MDCz 配置。配置修改后重启桥接；文件中的其他 MDCz 功能选项不代表已在 Miyabi 暴露。
3. 在同一 Compose 网络运行，两边分别持久化数据。桥接不映射宿主端口、不挂媒体库；生成至少 24 字符随机密钥，放在环境变量中，再填入 Miyabi 设置。不要把真实密钥提交到仓库。
4. 设置中使用 `http://mdcz-bridge:3840`，测试连接后保存启用。修改现有部署时保留原数据卷及 Emby 导出挂载；示例 Compose 是新环境模板，不能直接覆盖现有配置。
5. 用单片确认资料、简介、实际文件标签、NFO 和 Emby 封面；同片重试与二次重建应无叠标，再验证关闭增强与桥接离线。

没有在 J4125 实测内存、时延或真实站点连通性，不给出运行占用承诺。

## 升级、回滚与验证

分别升级 Miyabi 和 MDCz，一次只变更一方。先比对接入表所列行为；MDCz 差异集中在 adapter，协议变更时升级协议常量、引擎固定 SHA、测试与文档。需要升级的固定 SHA 位于 Go 服务常量、桥接 contract 和 Dockerfile，应一起变更，不能只改镜像标签。

升级验证顺序：协议/鉴权/取消→旧接口 golden→资料身份与部分失败→Plot 导入/保存/重建→原图/角标重试→实际文件变化→设置切换→单片 Emby 导出。原图及持久目录备份后再更新依赖。回滚可关闭增强，继续原刮削；回退到不认识 Plot/扩展字段的旧版本后，旧版本再次导出可能丢这些字段，因此代码回滚与数据备份必须一起考虑。
